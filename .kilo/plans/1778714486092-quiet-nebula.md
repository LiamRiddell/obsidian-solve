# Plan: Fix Duration/TimeSpan Handling

## Problem
- `:researchDays = 14 days` currently returns a raw number (milliseconds).
- User expects a "Timespan type" (or `ValueType.Uom`) that preserves the unit (e.g., "14 days").
- `:researchEnd = :startDate + :researchDays` should work with this new type.
- Support conversion syntax like "5 years in days".
- Variables show as "Percentage (days)" instead of "Timespan (days)" due to incorrect type mapping in UI.
- Arithmetic results return `0` due to incorrect type mapping and variable handling.

## Root Cause
1.  `en.ts` maps `days`, `weeks`, etc. to `DURATION_DAY` token type.
2.  `DurationPostfixParselet` handles `DURATION_DAY` tokens and emits raw millisecond arithmetic (`PUSH_NUMBER ms`, `MUL`).
3.  `DATE_ADD`/`DATE_SUB` in `VM.ts` only handle `ValueType.Number` (milliseconds), not `ValueType.Uom`.
4.  No support for "X in Y" conversion syntax (only "X to Y").
5.  `formatType` in `playground/src/engine.ts` has incorrect mapping for `ValueType.Uom` and `ValueType.Percentage`.
6.  Variable assignment and arithmetic logic might be broken due to type mismatches.

## Solution Steps

### 1. Update Lexer Keywords (`src/engine/constants/locales/en.ts`)
- Remove `days: "DURATION_DAY"`, `weeks: "DURATION_WEEK"`, etc. from `keywordMap`.
- This allows `ciKeywords` in `MarkdownLexer.ts` to fall back to `knownUnits` and tokenize them as `UNIT`.

### 2. Remove `DurationPostfixParselet`
- Delete `src/providers/datetime/parselets/DurationPostfixParselet.ts`.
- Remove its registration from `src/providers/datetime/parselets/index.ts`.
- `UomLiteralParselet` will now handle `14 days` (tokenized as `NUMBER` `UNIT`) and emit `UOM_CONVERT`, creating a `ValueType.Uom`.

### 3. Update `VM.ts` for Date Arithmetic
- Modify `OpCode.DATE_ADD` and `OpCode.DATE_SUB` to handle `ValueType.Uom`.
- When popping the duration, check if it's `ValueType.Uom`.
- If so, convert the value to milliseconds using `convertUnit(value, unit, "ms")`.
- Use the converted milliseconds for date arithmetic.

### 4. Add "IN" Conversion Syntax
- Add `IN` token type to `src/engine/lexer/Token.ts`.
- Add `in: "IN"` to `src/engine/constants/locales/en.ts`.
- Modify `src/providers/uom/parselets/UomLiteralParselet.ts` to check for `IN` token (in addition to `TO`) and emit `UOM_CONVERT_TO`.

### 5. Update Formatting
- `FormatEngine.ts` already handles `ValueType.Uom` via `formatUom`, which prints `= ${value} ${unit}`. This is correct.
- **FIX**: Update `playground/src/engine.ts` `formatType` function to correctly map `ValueType.Percentage` (5) to "Percentage" and `ValueType.Uom` (6) to "Timespan".
- **CLEANUP**: Remove unused `formatDuration` function from `FormatEngine.ts`.

### 6. Update Tests
- Remove tests for `DurationPostfixParselet`.
- Update `DatetimeParselets.spec.ts` to expect `ValueType.Uom` results.
- Update `FormatEngine.spec.ts` and `FormatFuzz.spec.ts` to handle `ValueType.Uom` or remove `ValueType.Duration` tests if we clean it up.
- Add tests for "5 years in days".
- **ADD**: Tests for variable assignment and arithmetic with `ValueType.Uom`.
- **ADD**: Integration test for the specific user scenario:
  ```
  :startDate = now
  :researchDays = 14 days
  :developmentWeeks = 6 weeks
  :testingDays = 5 days
  :researchEnd = :startDate + :researchDays
  :devEnd = :researchEnd + :developmentWeeks
  :projectEnd = :devEnd + :testingDays
  ```

### 7. (Optional Cleanup) Remove `ValueType.Duration`
- Since `ValueType.Uom` now handles time durations, `ValueType.Duration` is redundant.
- Remove from `src/engine/vm/Value.ts`.
- Remove formatting case from `src/engine/format/FormatEngine.ts`.
- Update any references (playground, tests).
