# Project Review & Improvement Plan

## 1. Current State Analysis

### Architecture Mismatch
- **Goal (Stellar Harbor Phase 2):** Single moo state-machine lexer, remove Preprocessor.
- **Current State:**
  - `src/engine/preprocessor/` still exists (`Preprocessor.ts`, `InlineSolveExtractor.ts`) and handles markdown removal, comments, and inline solve extraction via regex.
  - `src/engine/lexer/MarkdownLexer.ts` exists and uses moo states (`main`, `expression`, `inline`), but `main` and `expression` are identical (only expression rules). It does **not** handle markdown constructs (headings, lists, blockquotes, etc.) via moo states.
  - `src/engine/lexer/Lexer.ts` is a wrapper around `ExpressionLexer` which forces `MarkdownLexer` into `expression` state.
  - `src/engine/lexer/ExpressionLexer.ts` wraps `MarkdownLexer` with `initialState="expression"`.
  - `src/codemirror/MarkdownEditorViewPlugin.ts` uses CodeMirror's `syntaxTree` to mask markdown regions (headings, lists, etc.) and skips solving them. It then extracts expressions from non-masked lines.
  - `SolveHighlightProvider` uses `Lexer` (which uses `ExpressionLexer` which uses `MarkdownLexer` in `expression` state) line-by-line for highlighting.
  - **Key Insight:** The current `MarkdownLexer` is never used for full-document parsing; it's used line-by-line in `ExpressionLexer`. The "markdown" states in `MarkdownLexer` are never utilized because `ExpressionLexer` forces the `expression` state.

### Provider Coverage
- **Goal (Stellar Harbor Phase 4):** Full provider coverage.
- **Current State:** Need to audit `src/providers/` and `src/engine/providers/` for missing patterns (e.g., Vector syntax, UoM `convert`, Datetime `next/last`).

### Engine Isolation
- **Goal (Stellar Harbor Phase 2b):** Isolate engine from Obsidian-specific code.
- **Current State:** Check `src/engine/index.ts` and imports for Obsidian/Codemirror dependencies.

### Syntax Highlighting
- **Goal (Eager Harbor Phase 7):** Implement syntax highlighting.
- **Current State:** Check for `src/codemirror/SolveHighlightProvider.ts`.

## 2. Improvement Phases

### Phase 1: Lexer Overhaul (Priority 1)
**Goal:** Replace Preprocessor with Single Moo State-Machine Lexer.
**Steps:**
1.  Analyze `src/engine/lexer/Lexer.ts` and `src/engine/preprocessor/`.
2.  Implement `MarkdownLexer` using moo states (main, expression, inline, blockquote, list, etc.).
3.  Remove `src/engine/preprocessor/`.
4.  Update `MarkdownEditorViewPlugin` to use the new lexer.

### Phase 2: Provider Coverage Audit & Implementation (Priority 2)
**Goal:** Ensure all providers match the "Stellar Harbor" specification.
**Steps:**
1.  Audit `src/providers/` for missing implementations.
2.  Implement missing patterns:
    *   **Vector:** Change `[x, y]` to `(x, y)` syntax.
    *   **UoM:** Implement `convert X to Y` pattern.
    *   **Datetime:** Implement `next Monday`, `last Friday`, `days until X`.
    *   **Dice:** Implement `roll between X and Y`.
3.  Write tests for new patterns.

### Phase 3: Engine Isolation (Priority 3)
**Goal:** Make `src/engine/` portable for future npm package.
**Steps:**
1.  Audit imports in `src/engine/` and `src/providers/`.
2.  Move engine-specific utilities to `src/engine/utilities/`.
3.  Move engine-specific errors to `src/engine/errors/`.
4.  Ensure `src/engine/index.ts` exports clean API without Obsidian/Codemirror types.

### Phase 4: Syntax Highlighting (Priority 4)
**Goal:** Implement syntax highlighting as per Eager Harbor.
**Steps:**
1.  Check for `src/codemirror/SolveHighlightProvider.ts`.
2.  If missing, implement it.
3.  Integrate with `MarkdownEditorViewPlugin`.
