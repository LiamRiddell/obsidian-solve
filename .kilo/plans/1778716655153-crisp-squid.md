# Plan: Fix Tokens Panel Newline Display in Playground

**Issue**: The playground Tokens panel doesn't show newlines properly. When multiple lines are entered in the editor (e.g., "10 + 5 * 2" followed by other text), the tokens are displayed as one line instead of being grouped by their source lines.

**Root Cause Analysis**:
1.  In `playground/src/main.ts`, the `renderTokens` function is called with `result.tokens` (line 122).
2.  `result.tokens` comes from `runEngine` in `playground/src/engine.ts`.
3.  `runEngine` filters tokens: `tokens = rawTokens.filter(t => t.type !== 'WS' && t.type !== 'NEWLINE')` (line 218).
4.  Consequently, `result.tokens` does NOT contain `NEWLINE` tokens.
5.  The `renderTokens` function has logic to group tokens by line when `groupByLine` is checked (default). This logic specifically looks for `NEWLINE` tokens to split lines.
6.  Since `result.tokens` lacks `NEWLINE` tokens, the grouping logic fails to detect line breaks, resulting in all tokens being displayed as a single group/line.

**Proposed Fix**:
Change `playground/src/main.ts` line 122 to pass `result.rawTokens` to `renderTokens` instead of `result.tokens`.

**Verification**:
1.  `result.rawTokens` contains the full token stream including `NEWLINE` tokens.
2.  The `renderTokens` function already handles `NEWLINE` tokens correctly:
    -   When `groupByLine` is true: It iterates tokens, pushing `currentLine` to `lines` whenever it encounters a `NEWLINE` token.
    -   When `groupByLine` is false: It explicitly filters out `NEWLINE` tokens (`if (token.type === 'WS' || token.type === 'NEWLINE') return;`), so the ungrouped view remains unaffected.
3.  `playground/src/engine.worker.ts` already serializes and sends `rawTokens` in the worker message (line 15), so the data is available.

**Steps**:
1.  Edit `playground/src/main.ts`.
2.  Locate line 122: `renderTokens(result.tokens);`.
3.  Replace it with `renderTokens(result.rawTokens);`.

**Impact**:
-   The "Group by line" feature will correctly display tokens grouped by their source line.
-   The "Ungrouped" view will continue to work as before, filtering out newlines.
-   No other parts of the UI depend on `result.tokens` specifically; `renderTokens` is the sole consumer.
