# Plan: Create Playground Web App for Debugging

## Overview
Create a standalone web-based playground application similar to Ohm.js editor that allows debugging of the parser and tokenizer. This will be a dev-only tool, not bundled with the Obsidian plugin.

## Requirements
1. **Input**: Text box for entering expressions
2. **Output Display**:
   - Token coloring/highlighting (visualize lexer output)
   - Parselet/AST display
   - Execution results
3. **UI**: Dark theme, modern and clean design
4. **Scope**: Focus on low token usage, minimal dependencies

## Architecture

### Directory Structure
```
playground/
├── index.html          # Main HTML file
├── src/
│   ├── main.ts         # Entry point
│   ├── engine.ts       # Engine integration
│   └── ui.ts           # UI rendering
├── styles/
│   └── main.css        # Dark theme styles
├── package.json        # Playground-specific config
├── vite.config.ts      # Build configuration
└── tsconfig.json       # TypeScript config
```

### Implementation Steps

#### 1. Setup Playground Directory
- Create `playground/` directory in repo root
- Initialize with minimal `package.json`
- Add `vite` and `typescript` as dev dependencies
- Configure `tsconfig.json` for standalone build
- Setup `vite.config.ts` for development server

#### 2. Integrate with Existing Engine
- Create wrapper that imports from `src/engine/`
- Export required types and functions:
  - `ExpressionLexer` for tokenization
  - `Parser` for parsing
  - `BytecodeBuilder` for bytecode generation
  - `executeBytecode` for execution
- Create debug utilities to expose internal state

#### 3. UI Components
- **Input Panel**: Text area for expressions
- **Token Display**: Color-coded visualization of tokens
- **AST/Parselet Display**: Tree visualization of parsed structure
- **Results Panel**: Execution output
- **Error Panel**: Syntax/execution errors

#### 4. Styling
- Dark theme (dark grays, accent colors)
- Monospace font for code areas
- Syntax highlighting for tokens
- Responsive layout

#### 5. Build System
- Use Vite for dev server
- Hot module replacement
- Production build for static hosting

## Technical Details

### Integration Approach
Since the engine is built with esbuild and uses absolute imports (`@/`), we'll need to:
1. Re-export engine components from a wrapper module
2. Handle module resolution for TypeScript
3. Ensure tree-shaking to minimize bundle size

### Token Visualization Strategy
- Color-code by token type (NUMBER, OPERATOR, IDENTIFIER, etc.)
- Use inline spans with CSS classes
- Show token value, type, and position

### AST Display Strategy
- Use nested HTML structure for tree visualization
- Collapsible nodes for complex expressions
- Show node type and associated token information

### Fix for "global is not defined" Error
The `convert-units` package (a dependency of the main plugin) uses `lodash` internally, which tries to access the Node.js `global` object. This object does not exist in the browser environment.
- **Solution**: Add a shim in `vite.config.ts` to define `global` as `globalThis`.
- **Action**: Modify `vite.config.ts` to include `define: { global: 'globalThis' }`.
