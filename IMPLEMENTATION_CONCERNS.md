### Observations from Code Audit

#### 🔴 Critical for Nanosecond Ethos
1. **TypedArray re-allocation on every eval** (ExpressionEngine.ts:256-257) — `new Uint8Array()` and `new Float64Array()` called every eval even with cached bytecode. This is the #1 perf win.
2. **New VM created on every re-evaluation** (ExpressionEngine.ts:337) — `createVM()` allocates a new Map + array. Should reset/reuse.
3. **toNumber() not cached on Value** — called 3-5x on same Value in complex expressions. Safe to cache since Value is readonly.
4. **No safety limits enforced** — 4 bugs defined in config, zero enforced. Security/stability risk.
5. **NaN propagation** — `parseFloat("hello")` → NaN → corrupts entire expression tree silently.

#### 🟡 Architectural
6. **3 overlapping caches** (LineCache, MemoCache, UnifiedCache) with unclear ownership — confuses invalidation.
7. **Error framework unused** — `SolveError`/`Result<T,E>` exist but every error path uses `throw new Error()`.
8. **DependencyGraph.removeLine()** iterates ALL consumers — O(V) instead of O(k).
9. **DependencyGraph.registerLine()** doesn't clean up old references on re-registration.
10. **15+ `any` types** in production code undermines TypeScript safety.

#### 🟢 Future Enablers
11. **No `evaluateNumber()` fast path** — frontend only needs a number most of the time but gets a full Value object.
12. **No pre-compilation/warm-up API** — frontend can't pre-warm cache on vault load.
13. **No worker parallelism** — DataQueryWorker exists but isn't wired to ExpressionEngine.
14. **PluginSystem completely disconnected** from ExpressionEngine (hardcoded registrations).
